Compare the downloaded archive with its published checksum before use. Keep the helpers together and your repositories outside the app folder. These are portable archives, not installers.

Prefer to build from source?

  1. 1

    Install the tools

    Windows: the Rust MSVC toolchain, 1.89 or newer, with Microsoft C++ build tools, and Git 2.46 or newer.

    Linux x86_64: Rust 1.95 or newer, a C compiler and Git 2.46 or newer.

    macOS 15+ on Apple Silicon: Rust 1.99.1, the Xcode command-line tools, Node.js and Git.

  2. 2

    Get the source

    git clone https://github.com/JasXTD/Rocket.git
cd Rocket
  3. 3

    Build it

    # Windows
.\tools\Build-Local.ps1
# Linux
tools/build-local.sh
# macOS
bash tools/build-macos.sh

    Windows and Linux build the desktop app, the CLI and their helpers under target/release. macOS makes Rocket.app and a ZIP under target/macos-stage1. Plain cargo build compiles too, but turns Lua extensions off.

  4. 4

    Start Rocket

    # Windows
.\target\release\rocket.exe
# Linux
./target/release/rocket
# macOS
open target/macos-stage1/Rocket-macos-arm64-development/Rocket.app

    Help → Setup Guide walks you through a first local commit. Press F1 for the guide, or use the search field in the toolbar for the command palette.

What it uses

Windows x64The main platform. Testing has focused on Windows 10.
Linux x86_64X11 or Wayland, with your system Git. The portable 0.92.2 archive needs glibc 2.43+.
macOS 15+Apple Silicon, with your installed Git. Not yet notarized.
GitA build from a fresh clone uses the Git you installed. On Windows, HTTPS needs Git for Windows 2.56.0.windows.4 or newer; older builds stay on local and SSH.
Git Credential ManagerFor the supported browser sign-in flows.
OpenSSHFor SSH keys and profiles.
Git LFS 3.8.1+Only for Git LFS operations.
Claude Code or CodexOptional, for AI drafts, review and resolve.

Moving a Windows or Linux build? Keep every file from target/release together.

Current limits

  • macOS builds aren't yet signed with a Developer ID or notarized, and haven't been tested on a physical Mac.
  • On Linux, Lua extensions need x86_64 with Landlock.
  • Live acceptance for hosts other than github.com is still unverified.
  • Partial diff and stash actions support specific text and file cases.
  • Jira has been tested against mock services, not a live server.
  • The AI conflict page has been tested with a stand-in program, not a real reply.
  • The CLI and localhost MCP expose subsets of the desktop workflows.
