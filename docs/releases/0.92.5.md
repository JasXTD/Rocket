# Rocket 0.92.5

This release adds a Windows installer while retaining every portable package, expands Code Map across five language families, connects Agents to issues and pull requests, and adds dedicated Forgejo/Codeberg hosting. It also tightens repository-input limits, installer packaging and the review of text sent to agents.

## Highlights

- **Windows installer:** install Rocket for your Windows account, with Start menu and optional desktop shortcuts. Setup contains the same verified payload as the portable ZIP, including bundled Git and app-local runtimes. It does not require administrator access, change PATH, enable MCP or change your Git credentials and SSH configuration.

- **Code Map:** open folders become boxes, with arrows showing dependencies between files across Rust, JavaScript/TypeScript, Python and Go packages. Colour by file kind, commit activity, ownership or changes against a base; use Changed only to narrow the view. Ownership comes from CODEOWNERS when available, otherwise commit history. Maps read committed source without compiling or executing it; dynamic imports, macros and conditional compilation are not fully resolved, and the map is not a function-call graph.

- **Modules in more languages:** explore JavaScript, TypeScript, Python and Go alongside Rust. Move between package, folder and module views, inspect dependencies and open the corresponding history while preserving uncommitted files.

- **Agents connected to your work:** start a session from an issue, address pull-request review comments, fix failing checks or start from a failed CI run. Review the fetched text and the generated first message before creating the session. The first message stays in the input until you choose Send. Pull-request sessions start at the reviewed head and integrate through the guarded fast-forward Push flow; changed remote heads require another review. Save reusable tasks without saving the fetched message.

- **Forgejo and Codeberg:** Forgejo has its own account/provider entry, starting with Codeberg. It supports repository links, pull requests and issues, reviewed creation, inline reviews, merge/squash/rebase, Insights and Agents issue text. Actions shows runs on Forgejo 12+, jobs on 16+, and reruns failed jobs on 17+; older servers use commit statuses and explain missing capabilities. Forgejo review-thread reply/resolve/reopen controls remain read-only where its API cannot perform them.

- **Explore beyond GitHub:** search GitLab, Gitea and Codeberg, including configured servers. Public GitLab and Codeberg searches work without adding an account. Sort by stars or update time, use GitLab's language filter, and see host-specific rate-limit feedback. GitHub-only search qualifiers are identified before sending them to another host.

## Security and correctness

- Code Map now reserves its shared 10,000-file / 64 MiB source-read budget before both initial reads and Rust `#[path]` follow-ups. CODEOWNERS work is bounded across rules and wildcard matching, with cancellation inside the matcher. Incomplete ownership results are discarded and clearly identified; the UI falls back to commit-history ownership instead of presenting partial matches as complete.

- Installer packaging validates archive metadata without executing the archive's CLI. Input hashes and manifests establish byte consistency, not publisher identity. Packaging retains path/link checks, exact file inventories, credential detection and comparison against local SSH keys; unknown findings stop packaging.

- Host-sourced Agents messages require explicit acknowledgment tied to the exact reviewed text. Editing or rebuilding the message invalidates it. Quoting, sanitization and acknowledgment do **not** eliminate prompt injection: agents retain your ordinary file/network permissions, and a worktree is not a sandbox. Keep provider permission checks enabled and review proposed commands and changes.

- Security preferences place Total scan budget inside Secret protection. Dependency checks have explicit file-count, per-file and aggregate limits, with bounded batches and clear partial-result reporting. These settings apply to background and before-push checks; protection is not disabled by raising or lowering a budget.

## Interface and documentation

Summary uses the full window width. Actions empty states, the Stash menu and Map's labelled Export button are more consistent. SSH-key preferences fit smaller windows more reliably, and copy/scan feedback no longer adds rows that shift controls under the pointer. New labels extend the existing preview translations, with English fallback.

Third-party notices are now `THIRD-PARTY-NOTICES.md`, including the generator, Legal screen and packages. README and SECURITY.md reflect the current release, and the complete README Roadmap section has been removed.

## Install, update and uninstall

Windows Setup installs under `%LOCALAPPDATA%\Programs\Rocket` by default. Keep repositories and personal files outside its `app` folder. Setup upgrades and uninstall refuse unexpected, modified, linked or locked application files rather than deleting them. Uninstall preserves your saved settings, drafts, repositories, credentials, SSH keys and retained recovery backups. Help → Check for Updates continues to use the portable update ZIP; the uninstaller and shortcuts remain outside the swapped app folder. See the [installer guide](https://github.com/JasXTD/Rocket/blob/v0.92.5/docs/Windows-installer.md).

For portable packages, close Rocket and extract into a new folder. Do not overwrite a running installation. The Windows installer and Rocket executables are unsigned. Mac previews are ad-hoc signed, **not Developer-ID-signed or notarized**, and refuse in-app installation. Do not disable operating-system security protections to run a package.

## Validation and known limits

Release qualification verifies the protected source push, package inventories, versions, checksums, helper binding and local-key leakage. Focused security and native localhost MCP tests use temporary repositories, isolated profiles and mock hosting APIs. Windows installer acceptance covers installation, upgrade, cancellation, protected files and uninstall. Windows/Linux builds use locked local dependencies; Apple Silicon and Intel packages are built and checked on standard public GitHub runners.

These checks do not establish live acceptance for every non-GitHub hosting provider or Jira. Fresh Windows 11 acceptance, additional Linux distributions and physical Mac testing remain separate. An intermittent Intel spelling symptom previously observed in preview builds still has no confirmed cause; spelling remains part of package acceptance. Translations remain previews pending native-speaker and layout review.

Rocket does not install AI CLIs or change their logins. Providers may require separate subscriptions. New saved tasks and non-default dependency limits use newer settings formats; older builds may refuse those files rather than modify them. Back up settings before downgrading, especially after adding a Forgejo account.
